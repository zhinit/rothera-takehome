# Connection lifecycle in React

## Socket ownership and subscription lifetimes

React Effects synchronize components with external systems. Setup runs after a component commits. When dependencies change, React calls the previous cleanup with the old values before running the next setup with the new values. Cleanup also runs after removal. React describes each Effect as an independent start-and-stop synchronization process. (source: react-use-effect-2026.md) (source: react-effect-lifecycle-2026.md)

The browser WebSocket constructor immediately starts a connection attempt. React requires pure rendering, and a ref's initial-value expression is still evaluated on every render. Consequently, `useRef(new WebSocket(url))` starts connection attempts during rendering even though React retains only the initial ref value. This is an inference from the two APIs. A ref can retain a socket handle created outside rendering, but does not itself create, close, or deduplicate sockets. Each component instance has its own ref. (source: whatwg-websockets-standard-full-2026.md) (source: react-synchronizing-effects-2026.md) (source: react-use-ref-2026.md)

Transport ownership and asset subscriptions can have different lifetimes. Polymarket supports changing its asset set through subscribe and unsubscribe messages on an existing socket. Its archived SDK separates a connection object from a subscription registry, sends current subscriptions on open, and closes when no active subscriptions remain. These are observed implementation patterns, without selecting an application architecture. (source: polymarket-realtime-data-2026.md) (source: polymarket-sdk-websocket-clob-market-2026.md) (source: polymarket-sdk-websocket-clob-protocol-2026.md)

React's room-switch examples create a different connection when `roomId` changes. For a transport that supports subscription changes, the analogous synchronization can update subscriptions without replacing the transport. Separating those lifetimes follows from React's independent-process model and Polymarket's existing-connection operations. React does not impose a global singleton or prevent multiple components from independently creating sockets. (source: react-effect-lifecycle-2026.md) (source: react-use-effect-2026.md) (source: polymarket-realtime-data-2026.md)

## Cleanup and asynchronous shutdown

React's documentation pairs connecting with disconnecting, adding listeners with removing them, intervals with clearing them, and delayed callbacks with cancelling their timeouts. Its asynchronous request examples also set a local `ignore` flag during cleanup so obsolete results cannot update state. Cleanup of a network resource and invalidation of application work address separate consequences of setup. (source: react-use-effect-2026.md) (source: react-synchronizing-effects-2026.md) (source: react-separating-events-effects-2026.md)

WebSocket `close()` returns `undefined`. On an open connection it initiates the closing handshake and changes `readyState` to `CLOSING`. On an unestablished connection it fails the connection attempt and sets `CLOSING`. Calls on `CLOSING` or `CLOSED` do nothing after argument validation. A later queued task sets `CLOSED` and fires the close event. Therefore, React calling cleanup before the next setup does not imply that the previous transport has completed network shutdown. (source: whatwg-websockets-standard-full-2026.md) (source: react-use-effect-2026.md)

The archived SDK's manager shutdown stops its reconnect scheduler, ends subscriptions, and then awaits connection closure. The connection stops heartbeat and watchdog timers, clears its current socket reference, and guards message and close callbacks against a different current socket. The reconnect scheduler checks whether recovery is still wanted before running an attempt. These mechanisms illustrate cancellation of retries and rejection of obsolete connection callbacks. They do not establish that every asynchronous race is handled by that implementation. (source: polymarket-sdk-websocket-clob-market-2026.md) (source: polymarket-sdk-websocket-lifecycle-2026.md)

Dropping a JavaScript reference does not establish socket shutdown. The WebSockets Standard prevents garbage collection of connecting, open, and closing sockets under specified listener conditions, and of established sockets with queued outgoing data. (source: whatwg-websockets-standard-full-2026.md)

## Duplicate connections and dependency changes

Root StrictMode adds a development-only setup, cleanup, and setup sequence to expose missing cleanup. A StrictMode boundary below the root does not add the initial Effect rerun when that would produce child-only behavior unavailable in production. Extra development connection attempts can therefore be expected even with cleanup, while accumulated resources indicate an incomplete lifecycle. Because WebSocket shutdown is asynchronous, a closing old transport can temporarily coexist with its replacement. (source: react-strict-mode-2026.md) (source: react-use-effect-2026.md) (source: whatwg-websockets-standard-full-2026.md)

React explicitly warns that a ref used merely to prevent a second setup does not fix a leaked connection. Setup and cleanup must remain valid across remounts. An empty dependency array applies to each component instance and does not establish one connection across the application. (source: react-synchronizing-effects-2026.md) (source: react-use-ref-2026.md)

React compares dependencies with `Object.is`. New object, array, or function references can cause repeated synchronization even when their contents appear unchanged. The official examples move connection options and helper functions into the Effect and retain the reactive primitive inputs as dependencies. Suppressing required dependencies can leave installed callbacks reading values from an older render. (source: react-use-effect-2026.md) (source: react-effect-lifecycle-2026.md)

The archived SDK additionally reuses an open socket and retains an in-flight connection promise. These are explicit connection-manager mechanisms for handling repeated `connect()` calls. An Effect dependency array alone does not provide those guarantees across callers. (source: polymarket-sdk-websocket-lifecycle-2026.md) (source: react-use-effect-2026.md)

## Previous-game messages and obsolete work

The saved CLOB probe observed four delta items for removed A tokens in two messages 73 ms after switching to B. The capture establishes delivery after unsubscribe in that run, without identifying whether server processing or queued delivery caused it. Unsubscribe therefore does not establish an immediate barrier after which every received item belongs to the new game. (source: poking_around_api/2026-10-06-clob-websocket/analysis-result.json) (source: poking_around_api/2026-10-06-clob-websocket/observations.md)

The browser queues message delivery tasks and checks that the socket is `OPEN` before firing each message event. This does not track application subscriptions. On a retained open socket, an asset-membership check can reject items belonging to removed tokens. A socket-identity or connection-generation check instead rejects callbacks from a replaced transport. These checks cover different cases, inferred from the browser specification, SDK guards, and captured removed-token items. (source: whatwg-websockets-standard-full-2026.md) (source: polymarket-sdk-websocket-lifecycle-2026.md) (source: poking_around_api/2026-10-06-clob-websocket/analysis-result.json)

For `price_change`, membership applies to each item's `asset_id`. The documented message can contain multiple changed assets, and the SDK matcher accepts an entire event when any item matches the subscription. Accepting the envelope alone therefore does not imply that every item belongs to the selected game. Single-asset messages carry their asset identifier at the top level. (source: polymarket-clob-asyncapi-2026.md) (source: polymarket-sdk-websocket-clob-protocol-2026.md)

React's cleanup flag prevents an obsolete asynchronous result from updating state after its owning Effect is cleaned up. Applying that pattern to queued parsing, batched quote updates, or delayed callbacks requires checking validity when the work commits. A locally captured selection generation can similarly distinguish work queued during different selections, including A → B → A where comparing only the game ID would match again. This is a derived technique, without a benchmark or new socket experiment. (source: react-synchronizing-effects-2026.md) (source: react-use-effect-2026.md)

A local generation cannot recover provenance absent from a received frame. The archived CLOB subscription requests and event schemas provide no client subscription-generation identifier. If an old A frame first reaches the handler after A has been selected again, current-token membership and a generation captured at receipt cannot identify its earlier subscription lifetime. The cited sources do not establish a complete solution for that wire-level ambiguity. (source: polymarket-clob-asyncapi-2026.md) (source: polymarket-sdk-websocket-clob-protocol-2026.md)

The SDK sends the current registry state when a connection opens. This illustrates why a delayed open or reconnect can use current desired subscriptions, rather than a selection captured when connection establishment began. The mechanism is visible in the implementation, without establishing the behavior of any future dashboard. (source: polymarket-sdk-websocket-clob-market-2026.md)

## Current values and Effect Events

`useEffectEvent` returns a callback that reads the latest committed props and state without resynchronizing the surrounding Effect when those values change. It can be used in listeners or timers registered by a local Effect. Effect Events must be omitted from dependency arrays, cannot be called during rendering or from user event handlers, and cannot be passed to other components or Hooks. The current reference says their function identity changes on each render. (source: react-use-effect-event-2026.md) (source: react-separating-events-effects-2026.md)

Effect Events are limited to logic that should remain nonreactive. Values that should change subscriptions still participate in the synchronization dependencies. Reading current state also does not preserve an event's original identity: React's delayed room-notification example passes the originating room as an argument, while reading the latest theme inside the Effect Event. It separately clears the notification timeout to cancel obsolete work. Consequently, an Effect Event alone supplies neither old-message rejection nor cancellation. (source: react-use-effect-event-2026.md) (source: react-separating-events-effects-2026.md)

Refs also retain mutable values across renders without causing a render. React permits reading and writing them in Effects and event handlers, with a limited predictable-initialization exception during rendering. Mutating `ref.current` does not trigger synchronization and is not a reactive dependency. A displayed connection status therefore needs reactive state or a store subscription if the view must update when it changes. (source: react-use-ref-2026.md) (source: react-effect-lifecycle-2026.md) (source: react-use-sync-external-store-2026.md)
